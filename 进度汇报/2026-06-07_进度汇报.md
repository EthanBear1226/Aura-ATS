# 🚀 Aura 项目开发进度汇报 (2026-06-07)

## 📌 当前阶段：V2.7 (Newton-v1.18.0) 协同闭环与容器自愈加固

在本次开发周期中，Aura 招聘管理系统实现了核心的**多角色业务协同闭环**，并对云端生产环境（无状态容器）中的**临时数据防丢自愈**以及**成员注销管理安全**进行了深度加固，使系统距离高可用、高安全的企业级 SaaS 平台更近了一步。

---

### ✅ 已完成核心特性与重构

#### 1. 面试官与用人经理协同端口深度落地
*   **专属大盘与数据隔离**：实现了技术面试官 (Interviewer) 和用人经理 (HiringManager) 的专属工作台 Bento Grid 仪表盘，后端接口在核心数据上根据角色执行了严密的安全沙箱隔离（面试官仅可见与自己关联的日程；经理仅可见本部门职位的投递数据）。
*   **高效流转协同闭环**：
    *   **复筛联动**：用人经理点击“复筛通过”后，系统后端会自动触发并产生待办任务；HR 的工作台大盘会实时生成“协同排期任务”卡片。
    *   **一键排期销毁**：HR 点击协同待办可一键跨页面自动唤起“排期抽屉”；排期成功后，该待办任务自动标记为 `resolved` 予以销毁。
*   **反馈决策自动归档**：当面试官提交面试反馈且综合评定为“不满意/淘汰”时，系统会在后端自动联动更新候选人状态为“已淘汰”，将其自动归档进人才库。

#### 2. 无状态容器文件丢失自愈与持久卷挂载
*   **重新上传补全机制**：针对 Serverless 无状态容器（如 Zeabur）每次重启或重建导致本地 `uploads/` 中简历文件丢失的通病，我们为详情页新增了“重新上传简历”的功能入口。若检测到简历文件丢失（HEAD 请求返回 404），则自动引导用户点击上传覆盖，且**完全不破坏原有的 AI 解析、匹配度打分和日志等结构化数据**。
*   **指导挂载持久卷**：成功引导用户在 Zeabur 顶部控制面板将持久化网盘 (Volume) 挂载至 `/app/uploads`，实现了上传文件的底座物理级永久留存，彻底根治了重启丢失问题。

#### 3. 企业协同成员管理升级（注销与防自锁）
*   **安全注销删除**：新增 `DELETE /api/auth/invite/{invite_id}` 接口，支持对已邀请协同成员（包含 `pending` 等待激活与 `accepted` 已接受状态）的安全移除与注销。
*   **级联物理抹除**：若删除对象已经激活，接口会自动对 `user_invitations` 与 `users` 账户表执行级联清理，彻底取消其一切系统登录权限，拒绝后门残留。
*   **管理员防自锁机制**：强制进行账户自锁保护拦截，绝对禁止当前登录账户删除自己本身，防范因失误操作导致系统无人管理的死锁故障。
*   **前端操作集成**：在“协同成员邀请”表格中引入了单独的“操作”列与红色的“删除”按钮，并加入了 `showConfirm` 二次确认机制与动态 Toast 气泡。

#### 4. 稳定性加固与强缓存白屏修复
*   **清除版本强缓存**：针对多轮合并导致的 `app.js` 残留语法冲突，在修复解析报错的基础上，将全站所有页面引入 JS 的版本后缀由 `v=11` 统一升级为 `v=18`，强制拉取最新 JS 代码，彻底解决了浏览器读取错误强缓存导致页面白屏的死结。
*   **Lucide 图标依赖补齐**：在 `index.html` 头部补充引入了 Lucide 图标的 CDN 脚本包，修正了因 `lucide is not defined` 阻断 DOM 渲染的运行时错误。

### 🔮 下周开发工作规划

为了进一步加速 V3.0 版本的商业化推进，我们规划了下周（2026-06-08 至 2026-06-14）的重点攻坚工作：

#### 1. 投递与获取链接闭环 (Portal & Public Apply)
*   **外网职位投递门户**：打通面向求职者的外网投递公共链接（Portal Page），支持求职者在前台界面自主上传 PDF 简历。
*   **实时解析提醒**：求职者外网自主投递后，系统自动后台调用 Gemini 进行简历结构化解析并入库，同时在大盘实时为 HRBP 推送新简历提醒动态，完成“求职-投递-解析-处理”全链路闭环。

#### 2. 可视化 Kanban 看板流转落地
*   **卡片式拖拽看板**：在候选人列表页（Candidates）新增拖拽式看板（Kanban View）视图，支持将候选人卡片从“初筛”到“已入职”的跨节点无缝拖拽。
*   **拖拽接口联动**：实现拖拽时自动发起 API 请求（PATCH 接口更新 stage，自动录入 timeline 流转日志），告别繁琐的详情页按钮操作。

#### 3. 云端对象存储 (OSS) 集成
*   **接入 S3/R2 云存储**：为彻底解决无状态容器下本地存储（哪怕挂载了持久卷也有容量和区域限制）的局限，后端将集成对象存储 SDK（支持 Cloudflare R2、腾讯云 COS 或阿里云 OSS）。
*   **简历文件云端托管**：简历文件上传时，将简历 PDF 物理文件直接同步安全分发至云端对象存储，并把云端公共只读 CDN 地址作为候选人的 `pdf_path`，保证文件预览的极致加载速度与永久可靠性。
