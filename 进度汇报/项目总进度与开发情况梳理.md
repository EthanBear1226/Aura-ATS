# Aura 灵犀招聘系统 (ATS) - 项目总进度与开发情况梳理

**文档生成日期**: 2026年4月17日
**项目定位**: 一款基于大语言模型 (LLM) 驱动的现代化智能招聘管理系统，包含候选人追踪、AI 简历深度解析、自动化面试安排等核心全栈功能。

---

## 📈 项目当前总体状态

**目前阶段：V2.5 (交互现代化与 AI 轮询高可用版)**
项目已从早期的“纯前端静态 Mock 演示”彻底进化为“前后端分离、数据库持久化、AI 真实接入”的生产级雏形。核心业务闭环（候选人投递 -> AI 解析入库 -> 状态流转 -> 面试安排）已完全跑通，且具备在公网（如 Zeabur 等 PaaS 平台）稳定演示的能力。

---

## ✅ 已完成的核心里程碑与功能清单

### 1. 工程化基建与全栈架构部署
*   **技术栈确立**: Python (FastAPI) + SQLite (SQLAlchemy ORM) + 原生前端 (HTML/CSS/JS)。
*   **同源部署架构**: 废弃前后端独立部署，使用 FastAPI 的 `StaticFiles` 挂载前端静态资源，实现单服务器全栈拉起，极大降低了部署与维护成本。
*   **云原生适配**: 编写了标准化的 `Dockerfile`，并引入了动态 `PORT` 环境变量，使得项目能够完美适配 Zeabur 等现代云 PaaS 平台，实现了一键部署与更新。
*   **版本控制规范**: 建立了 GitHub 仓库，配置了严谨的 `.gitignore`（屏蔽虚拟环境、数据库文件、敏感 `.env` 凭证），并完成了多次核心迭代的合并与推送。

### 2. 数据库与持久化管理
*   **真实数据落盘**: 彻底移除了早期的 LocalStorage 方案。候选人信息、操作日志全面接入 SQLite (`aura_db.db`)。
*   **简历原件托管**: 实现了 PDF 文件的真实上传与服务器本地存储 (`uploads/` 目录)，不再依赖 Base64 转译，优化了性能并支持前端通过相对路径直接预览。
*   **数据模型拓宽**: 随着业务深入，对 `models.py` 进行了表结构变更，新增了 `email` 等关键字段，以支持后续的自动化邀约闭环。

### 3. AI 引擎深度集成与鲁棒性优化
*   **结构化信息提取**: 接入 Google Gemini API，通过强大的 Prompt 工程，强制大模型输出标准化的 JSON 数据（包含姓名、岗位、经验、邮箱、核心技能数组）。
*   **业务价值洞察**: 首创 AI 简历总结机制，除基础信息外，要求大模型输出高业务价值的 **“50字背景概括”** 和包含亮点与风险的 **“100字深度解析点评”**。
*   **智能模型轮询 (Auto-Discovery & Fallback)**: 针对免费 API 额度易耗尽（如 429 错误）和旧模型下线（如 404 错误）的痛点，开发了智能模型轮询策略。系统会优先尝试高免费额度的最新轻量模型（`gemini-2.5-flash-lite`, `gemini-flash-lite-latest` 等），极大提升了线上演示的可用性与稳定性。
*   **高质量降级演示模式**: 在彻底断网、未配置 API Key 或所有模型额度均耗尽的极端情况下，系统会无缝降级并注入高质量的“虚拟精英简历”数据，确保产品演示永不宕机。

### 4. 前端交互体验 (UI/UX) 的 SaaS 级重构
*   **全局轻通知与现代确认框**: 彻底废除了浏览器原生的、阻断式的 `alert` 和 `confirm`。自主封装了顶部平滑滑出的非阻塞 **Toast 轻提示**，以及带有毛玻璃背景 (Blur) 的**现代化 Confirm 模态框**（如删除警告），全面对标一线大厂 SaaS 体验。
*   **“一条龙”纵向审查布局**: 候选人详情页去除了繁琐的 Tab 切换，采用纵向流式排版（顶部 AI 概括 -> 中部技能与深度点评 -> 底部 PDF 原件内嵌），使 HR 的阅卷视线更加连贯。
*   **右侧滑出式抽屉 (Drawer)**: 将核心的“安排面试”功能重构为从右侧滑出的现代化 Drawer 交互。HR 在操作时不会丢失底层列表或简历详情的视觉上下文。
*   **上下文防错锁与并发保护**: 
    *   在列表或详情页点击“面试”时，系统会自动携带该候选人的上下文（如姓名、邮箱）填入 Drawer 表单，并置灰锁定候选人选择框，防止误操作。
    *   修复了多用户并发上传简历时的“视图错乱”问题，上传解析成功后强制重定向至唯一的候选人 ID 详情页。

## 🚀 下阶段开发演进蓝图 (Roadmap)

1.  **职位管理模块双向打通 (Job Management)**
    *   现状：`jobs.html` 目前仅有静态 UI。
    *   目标：与后端数据库联调，实现真实职位的发布、上下线。
    *   价值：允许候选人投递至特定职位，为后续的匹配打分奠定数据基础。
2.  **AI 智能人岗匹配打分 (AI Matchmaking)**
    *   目标：将具体的职位描述 (JD) 与候选人经 AI 解析后的结构化简历数据进行多维度的向量比对或提示词分析。
    *   产出：生成 0-100 的“系统推荐匹配分”，并附带匹配维度的雷达图或简评。
3.  **真实生态集成 (Ecosystem Integration)**
    *   目标：走通第一笔真实的外部协同 API。
    *   场景：使用真实的 SMTP/企业邮箱服务自动发送面试邀约邮件；或尝试拉取一段真实的公共日历数据渲染面试官闲忙看板。
4.  **数据库生产环境迁移**
    *   目标：在业务量上升前，将底层的 SQLite 平滑切换配置为线上的 MySQL 或 PostgreSQL 集群。
