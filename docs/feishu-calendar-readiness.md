# 飞书日历接入准备（2026-10-19）

## 本轮边界

本轮不申请飞书权限、不发起 OAuth、不读取真实日历、不创建飞书事件。
生产 provider 仍为 PendingFeishuProvider；配置凭据或开启开关不能直接接通。
默认只检查 Aura 内部面试，页面和成功提示明确说明尚未检查/同步飞书。

## 已准备的接入点

- `calendar_service.CalendarProvider.busy_intervals(identity, start, end)` 是未来适配器边界。
  输入为带 +08:00 时区的完整查询窗口，返回完整的带时区忙碌区间列表。
  空列表只能表示成功读取完整窗口且无忙碌；超时、权限不足、令牌过期、分页不完整、响应异常必须抛错。
  对外只输出忙闲，不返回会议标题、参与人或日程详情。
- `CalendarIdentity` 新表按内部面试官 ID 绑定飞书应用范围内的 `open_id`，唯一约束防止重复绑定。
  GET/PATCH/DELETE `/api/settings/interviewers/{id}/calendar-identity` 仅管理员可操作。
  PATCH 请求体示例：`{"feishu_open_id":"ou_example"}`。绑定值需从未来授权/企业人员流程取得，不能从姓名猜测。
  当前不提供空的授权按钮；未取得真实 ID 时无需填写。删除面试官会清除绑定。
- `GET /api/calendar/freebusy?interviewer_id=1&date=2026-11-02` 返回对象，包含
  `external_status`、`scope`、`timezone`、`message`、`checked_at`、`slots`。
  旧 `interviewer=姓名` 查询仍接受，但返回结构已经由数组改为对象；内置排期抽屉同步更新。
- 时间以 Asia/Shanghai 展示，旧无时区数据库值按中国时间解释；带时区提交先转为中国时间再保存。
  区间按 `[start, end)` 判断，相邻面试不冲突，跨小时/跨日期重叠会阻止安排。
  当前时段固定为一小时，9/10/11/13/14/15/16/17 点开始。
- 提交面试时重新查询冲突；身份 ID 决定真实面试官姓名，不信任客户端传入的姓名。

## 状态与配置

| external_status | 意义 | 是否允许安排 |
| --- | --- | --- |
| not_connected | 开关关闭，未检查飞书 | Aura 无冲突时可选；需要人工确认飞书 |
| unbound | 开关开启，但无身份绑定 | 禁止安排 |
| unavailable | 开关开启，但接口未实现或读取失败 | 禁止安排 |
| connected | 完整查询成功 | Aura 和飞书均无冲突时可选 |

`slots[].external_busy` 未确认时为 null；不能将 null 当作 false。
`slots[].isFree` 是当前模式下是否可选择，不等价于飞书空闲；应结合状态及 label 展示。
查询失败会清空旧时段；切换日期或面试官会丢弃旧请求结果。
`FEISHU_CALENDAR_ENABLED=false` 为默认值。误开启时失败关闭，不回退为“飞书空闲”。
`.env.example` 中的应用凭据和回调地址只作预留，当前无回调路由，也不会消费这些凭据。

## 权限具备后的一次接入工作

1. 确认企业自建应用、目标租户、可见成员范围和所用用户身份体系；本轮仅预留单应用的 open_id。
   按届时飞书官方文档核对忙闲查询和事件创建接口、所需权限及应用/用户令牌类型，取得管理员批准。
   若需要多个租户或更换应用，先扩展租户/应用维度及联合唯一键，不能复用另一应用的 open_id。
2. 实现服务端授权回调（state、防重放、错误回跳）、加密令牌存储、刷新、吊销和重新授权。
   秘钥只能在部署环境配置，不进浏览器、不进 Git、不写入日志。后台展示连接状态与撤销入口。
3. 在 factory 中换入真实适配器，配置 HTTP 超时、限流退避和完整分页；区分权限不足、过期、网络故障。
   保留失败关闭策略，测试全天事件、跨日事件、时区、忙闲类型及私人日程的隐私行为。
4. 另行实现事件创建、改期、取消及外部事件 ID 保存，采用幂等键和可靠任务重试。
   Aura 保存成功和飞书同步成功分别展示，不能把“本地保存”显示为“日程已锁定”。
5. 开启真实查询前先用专用测试账号验收：真实忙闲、重复点击、权限撤销、令牌过期、429/5xx、跨日改期、取消同步。
   测试通过后再开启生产开关。

## 已知限制与上线前条件

- 历史 Interview 仍按姓名关联归属，本轮绑定表使用稳定 ID，但没有迁移历史排期。
  同名配置会明确拒绝排期。真实接入前应将 Interview/User 关联迁为稳定 ID，并规划改名和历史回填。
- 本地提交前复查不能消除并发写入竞争，也不能锁住用户在飞书另建的会议。
  真实接入前应按面试官串行化提交/数据库锁，并在创建事件前复查，定义冲突补偿流程。
- 尚无 webhook、事件写入、后台同步任务或会议室资源预订；地点/链接仅保存用户手工填写内容。
  邮件仍沿用已有服务，当前界面不承诺发送成功。
- 只做本地隔离测试和模拟 provider 验证，没有真实飞书集成验收。

## 验证入口

后端门禁：`python run_tests.py`（显式纳入 test_calendar_api）。
前端模拟回归：安装 Playwright 和 Chrome 后运行 `node calendar-check.cjs`。
测试 provider 只在测试时注入，不会作为线上默认 provider。
