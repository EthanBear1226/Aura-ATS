工作台 2.0 详细设计 (Section 3/3)

最后一环：定义后端数据接口与自动化触发逻辑，确保数据的实时性与准确性。

API 规格与数据流

1. 核心 API: GET /api/workbench/summary

该接口将根据当前 localStorage 或 Session 中的用户角色返回定制化 JSON：

{
  "user_role": "Interviewer",
  "today_interviews": [
    { "id": 101, "candidate": "刘晨", "time": "14:30", "room": "A1" }
  ],
  "stats": {
    "total_reviewed": 45,
    "avg_score": 88
  },
  "notifications": [
    { "text": "HR 提醒你提交李思齐的反馈", "level": "urgent" }
  ]
}

2. 自动化感知逻辑 (Non-Action)

  • 简历解析监听：当 /api/parse_resume 完成后，如果得分 > 85，自动向该职位的负责 HR 发送工作台“高分预警”通知。
  • 面试状态联动：面试结束后（当前时间 > 面试结束时间），工作台自动弹出“待填写评价”磁贴，直到评价提交为止。

3. 实时性保障

前端 app.js 将在进入工作台页面时发起并发请求，并利用 sessionStorage 缓存已拉取的数据，减少页面跳转时的闪烁感。
